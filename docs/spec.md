# hatsunichi 仕様書

11/8 に出す版の仕様。更新 2026-11-05。「未実装」と書いた項目は、この文書のあとに作る。行番号は書かず、ファイル名で示す。

## 1. 遊びの流れ

鳥取市の 7 つの町を、朝 9 時から夕方 17 時まで歩く。町の人から人手の困りごとを聞き、町の数字を手帳に集め、案を 1 つ選んで根拠の数字と出典をそろえ、市の窓口へ出せる 1 枚にする。案を出さずに歩くだけでもよい。

7 つの町は 鳥取駅周辺 eki、雲山 kumoyama、湖山 koyama、福部 fukube、気高 ketaka、用瀬 mochigase、鳥取砂丘 sakyu。

### 1.2 依頼の場所の段

| 段 | すること | 次へ |
|---|---|---|
| hint | 近づいたときの一言 | 送ると ask |
| ask | 町の人の声と案 3 つ。話していない人は「まだ聞いてない」と出る | 案を選ぶと basis、「自分で書く」で write |
| write | 60 字まで自分で書く。調べた数字に無い数字があれば注意を出す | basis |
| basis | 根拠にする数字を 1 つ選ぶ。選ばないと案は出せない | calc があれば calc、無ければ place |
| calc | その町の数字を使う小さな計算。前提を動かすスライダーに「推定」と出る | place |
| place | 手帳に入った未活用施設から、使う場所を 1 つ選ぶか「場所は決めない」。同じ町の施設を先に並べる。手帳に施設が 1 つも無ければ飛ばす | result |
| result | 判子を押し、付箋（良い点・抜け・問い）を出す。確認役に見せるボタンは 6 章 | とじる・書き直す・くわしく |

確定すると、その回の答えに入る。同じ場所の古い答えは置き換わる。

### 1.3 操作

- 歩く: 矢印キーか WASD。Shift か、1.2 秒歩き続けると走る。歩きは秒速 7 単位、走りは 17 単位
- Space / Enter: タイトルで始める、歩いているときは話す、会話の中では送る
- 数字キー: バスの行き先、案、根拠、使う場所
- Esc: バス・くわしく・手帳を閉じる、write から戻る
- 入力欄に字を打っている間は移動キーを拾わない
- タッチ: 十字キー 4 つ。計算のスライダー
- URL に `?debug` を付けると `window.__town` にシーンを出す

### 1.3.1 歩かずに案を出す

題の画面の「歩かずに案を出す」は、時間の無い人と審査のための入口。白兎の話を飛ばし、依頼の一覧を出す。一覧は依頼ごとに、頼む人のひと言と町の名前。選ぶとその場所の手前へ移って依頼が開き、閉じると一覧へ戻る。3 つそろうか「終業にする」で終わりの画面。「このあたりを歩く」で歩けて、左下の「依頼の一覧」で戻れる。

一覧の上に「気になっている困りごとから探す」を置く。学生が自分の地元の困りごとを一行で書くと、案内役の Claude が 9 つの依頼から近いものを 1 つと、その依頼の根拠 3 つから候補を 1 つ選び、理由を 1〜2 文で返す。返せる値は構造化出力の enum で、依頼の id と none、根拠の番号 0〜2 に絞る。理由に一行に無い数字があれば 3 回まで作り直させ、残れば数字を伏せる。「この一行を自分の案にする」で、その一行を自分の案として依頼の場所の根拠を選ぶ段から始める。近い依頼が無ければ、根拠の数字が無いので 1 枚にはできないと書き、市政提案へ自分で出せることを示す。候補の根拠には印を付けるだけで、選ぶのは本人。鍵が無いときは、例の 8 行は記録（`data/routes-recorded.json`）を出し、それ以外は漢字とカタカナの 2 文字の重なりで選ぶ。どちらで選んだかを画面に書く。測定は `npm run record:routes`、結果は `docs/eval/route-*.md`

はじめてから 1 枚目を決めるまでの実時間を、終わりの画面と「書き写す」の 1 枚に「1 枚目まで約 N 分」と出す。試用で、出典つきの案を 1 枚作るのにかかった時間を測るため。どこにも送らない。

### 1.4 時間と終わり

- 時計は歩いている間だけ 1 秒に 0.7 分進む。画面を開いている間、バスに乗っている間、タイトルでは止まる
- 画面を閉じるたびに 10 分足す。バスは経路の km を時速 25 km で割った分を足す
- 何もしなければ 9:00 から 17:00 まで実時間で約 11 分 26 秒
- 17:00 を過ぎるか、案が 3 つそろうと終わりの画面へ移る。画面が開いていれば閉じてから
- 歩くだけのモードでは、白兎の話が無く、時計と判子を出さず、終わりの画面へ移らない。手帳は使える

## 2. 見つけるもの

近くを通ると手帳に入る。手帳は回をまたいで残る。

| 種類 | 手帳の id | 数 | 拾う距離 | 中身 | 作るもの |
|---|---|---|---|---|---|
| 依頼の場所 | `spot:<id>` | 7 | 2.2 単位 | その場所の数字 3 つ | 手で書く。数字は出典つき |
| 町丁の「?」の札 | `mark:<id>` | 32 | 3 単位 | 町丁の人口、65 歳以上の割合、5 年の増減、いちばん近い病院と小学校までの直線距離 | `scripts/build_marks.py` |
| 未活用施設の札 | `fac:<id>` | 6 | 3 単位 | 施設名、用途、延床面積、建った年、緊急避難所の指定。「今も使われていないかは未確認」と書く | `scripts/build_facilities.py` |
| バスの移動 | `ride:<a>|<b>` | 21 組 | 着いたとき | 2 つの町のまっすぐの距離 | 町の座標から計算 |

- 手帳に入った札は町で薄くなり、地図から消える
- 手帳の町ごとの合計は、依頼の場所・「?」の札・未活用施設の札の数
- 町の合計がそろったら「◯◯を歩ききった」と知らせ、手帳の町の見出しに「歩ききった」を付ける。読み込んだ時点でそろっていた町は知らせない

## 3. 1 枚の書式

終わりの画面の「書き写す」で、次の順にクリップボードへ写す。

```
はつにち 初日の記録

自分が手伝えること: …        ← 入力があるときだけ

■ {依頼の題}
案: {案の全文 or 自分の一行}
根拠: {選んだ数字の文}
出典: {出典名} {URL}
計算: {計算の一文}                    ← 計算を載せたときだけ
計算の根拠: {根拠の行に無い出典の数字}  ← 計算が別の数字も使うときだけ
計算の前提（推定）: {本人が動かした前提の名前}
前提の置き方: {本人が書いた一言。40 字まで}  ← 書いたときだけ
関わる人: {町}の {k} の町丁に住む {n} 人。65 歳以上が {m}%、9 つの町の 42 町丁の合計では {M}%。5 年で {d} 人減った 出典: {札の出典名}   ← 町丁の札がある町だけ。札の人口と増減の合計
自分は: {頼んだ人の一問に選んだ答え。例: 月に1回なら来られる}  ← 答えたときだけ
使う場所: {施設名}、{町}。鳥取市の未活用施設。今も使われていないかは未確認 出典: {出典名}   ← 選んだときだけ
参考: 市の施設の使い方は 鳥取市 公共施設マネジメント民間提案制度 で民間から募っている。この施設の案を市が募っているわけではない {URL}   ← 選んだときだけ
まだ確かめていないこと: {問い} / {問い}
確認役の問い: {問い}（{モデル名}、{日付} の記録）   ← 確認役の付箋があるときだけ。記録なら日付、自分の鍵で読ませたなら日付なし
出す先: 鳥取市 市政提案 市長への手紙 https://www.city.tottori.lg.jp/site/shiseiteian/
担当の窓口: {窓口名} {URL}        ← 出す先と違うときだけ

■ 見つけたこと
- {本文} 出典: {出典名}
```

「参考」の行は、市がその施設の案を募っているわけではないので、出す先にはしない。

終業の画面で「事業の構想として持ち帰る」を選ぶと、見出しの後ろに「（事業の構想として）」が付き、最後の 2 行が次の 3 行に替わる。「出したら記録」は出さない。

```
この困りごとの担当: {窓口名} {URL}
事業の相談先: 鳥取市 中小企業・小規模企業支援制度（令和8年度） https://www.city.tottori.lg.jp/page/5160.html
相談先について: {制度ごとに問い合わせ先の課が違うこと。この案に合う制度があるかは未確認}
```

## 6. 確認役 Claude

1 枚に付箋を 1 枚付ける。良い点 1・抜け 1・問い 1。

- 動かす場所: 手元のサーバー `scripts/review-server.ts` だけ。API キーは手元の `.env` の `ANTHROPIC_API_KEY` に置き、ブラウザにも公開リポジトリにも置かない
- 公開版 GitHub Pages: サーバーを持たないので、確認役のボタンを出さない。付箋は world.json に書いた決まった付箋を出す
- 手元で動かすとき: `npm run review` でサーバーを立て、`NEXT_PUBLIC_REVIEW_URL=http://localhost:8787/review` を付けて `npm run dev`。result 段の左上に「確認役に見せる」が出て、押すと付箋が貼られる。町の 1 枚は同じサーバーの `POST /sheet` に送る
- サーバーが受け取るのは、依頼の場所の id、選んだ案の番号か自分で書いた一行、根拠の番号、計算の前提の値、施設の id だけ。1 枚の文はサーバーが world.json と `src/lib/calcs.ts` から組み直す。自分で書いた一行は画面と同じ 60 字まで、前提の値は画面のつまみの範囲の中だけ。組み直しは `src/lib/sheet.ts` の `answerFromRequest`
- 数字の見張り: 付箋の数字が 1 枚の文に無ければ作り直させる。1 桁と時刻は拾わない。3 回通らなければ数字を伏せて返す。作り直した回数を記録する
- 1 枚は `<sheet>` で囲んで渡し、中の指示には従わないとシステムプロンプトに書く。一行に書かれた `<sheet>` の札は消してから渡す
- サーバーは 127.0.0.1 でだけ待ち受ける。Origin 付きの呼び出しは localhost と 127.0.0.1 の画面だけ受け、ほかは 403。本文は 4KB まで。1 時間に 10 回まで
- モデルは `REVIEW_MODEL`。無ければ `claude-opus-5-5`。出力の形は構造化出力の JSON スキーマで決める。Opus 5.5 は道具の強制呼び出しを受け付けないため。安全の判定で断られたときは `fallbacks: "default"` で別のモデルに回す。キーが無ければ決まった付箋を返す
- 測定: `npm run eval:sheet`。依頼の場所ごとの 3 つの案と、一行に指示や作った数字を混ぜた 3 件。結果は `docs/eval/sheet-<モデル>.md`。キーで測るまでは demo の結果だけ
- 返事の予行: 市政提案に出す 1 枚を、市の担当者役の Claude が読み、返事を書く前に本人へ聞き返す問いを 1〜3 つ返す（`rehearseReply`）。実在の市の返事ではなく、本人が答えを用意しておくための練習。数字の見張りと `<sheet>` の囲みは付箋と同じ。鍵の無い人には、`RECORD=1 npm run record:replies` で記録した案 × 根拠の 81 通りが `data/replies-recorded.json` から終業の画面に出る。自分の一行は、確認役に入れた鍵でブラウザから読ませる。「書き写す」の 1 枚にも載る。問いの下に答えを 140 字まで書いておけ、写しでは問いの次の行に「用意した答え」として載る。答えに 1 枚に無い 2 桁以上の数字があれば、その数字を名指しする。止めはしない。鍵も記録も無い自分の一行には、その依頼のまだ確かめていないことを問いにし、Claude の問いではないと書く。この問いは 1 枚の「まだ確かめていないこと」と同じなので、写しには答えを書いたときだけ載せる。記録は `docs/eval/reply-<モデル>.md`

作業台 /map の提出用紙にも、同じサーバーの `/review` が付箋を付ける。

## 7. 出典と表示

- タイトルと右上の地図の下に出典を出す。町丁の「?」は e-Stat と国土数値情報、施設は鳥取県オープンデータポータルの鳥取市の未活用施設の一覧を加工したもの
- タイトルの注記: 数字・施設・窓口は実在の公開情報。町の人・家・店・事業者は架空。試作で、市・県・バス事業者とは関係ない
- 施設の札の文は「今も使われていないかは未確認」で終える。使う場所の段に「鳥取市の未活用施設の一覧から。市がこの場所の案を募っているわけではない。今も使われていないかは未確認」と出す
- 窓口は公式ページへのリンクだけにし、電話番号とフォームは載せない
- 写真・ロゴ・図は使わない。市のサイトでは掲載部署の承認が要るため

出典の一覧と規約は `data/SOURCES.md`。

## 8. 外への通信

- 町の画面が読むのは同じサイトの中のファイルだけ
- 作業台 /map は国土地理院の淡色地図タイルを読む
- 外のリンクは新しいタブで開く。窓口、出す先、出典
- 確認役のサーバーだけが Anthropic の API を呼ぶ
- 文字はビルドのときに Google Fonts から取る。見る人のブラウザは取りに行かない

## 10. 公開

### 10.1 確認役の中継（置き場所が決まったら）

公開版で、鍵の無い人も自分の一行を live の Claude に読ませられるようにする Cloudflare Worker が `relay/worker.ts`。作者の鍵で呼ぶので、置くには Cloudflare のアカウントが要る。手順は `relay/wrangler.toml` の冒頭。

- 受け取るのは `POST /sheet`（付箋）と `POST /rehearse`（返事の予行）。中身は手元のサーバーと同じ番号だけで、1 枚の文は Worker が world.json から組み直す
- 守り: Origin は `ALLOWED_ORIGIN`（既定は公開先）だけ。本文 4KB まで。同じ IP は 1 時間に 10 回まで。1 日の合計は `DAILY_MAX` 回（既定 200）まで。回数は KV に置き、期限で消える
- 鍵は `wrangler secret put ANTHROPIC_API_KEY`。コードにもリポジトリにも置かない
